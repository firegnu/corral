# 在项目里启用 corral-dispatch

corral-dispatch 技能只管「怎么派」。要让主控在你描述完任务、说「开始」时，自动拆开派给别的 agent，项目的 AGENTS.md 里要写明两样东西：这个项目要派，以及几个项目参数。交给哪家、几档、要不要交叉审查不用写：交给哪家由主控照技能里的分工表定，另外两样由技能里的路由和主控定。新项目和现有项目都照这份加。

> 这个文件故意不叫 AGENTS.md：Codex 会把所在目录里的 AGENTS.md 当成给自己的指令来读。

## 1. 加进项目 AGENTS.md 的一节

复制下面这一节，把尖括号里的内容换成这个项目的：

```markdown
## 开发方式（主控分派）

- 这个项目的开发任务由主控拆开，派给别的 agent 做。主控负责拆任务、写任务文件、审查、合并，不自己写功能代码。分派时按 corral-dispatch 技能做。
- 被委派的 agent（任务文件里写明了身份）照任务文件做，不再往下派。
- 需求单只写用户要的结果；验收照抄用户原话，不补验收点。主控觉得该加的，列出来问用户。
- agent 名字以 `<项目>/dev-` 开头；任务文件放 `docs/tasks/`；每个任务一个分支，worktree 放 `../<项目>-worktrees/<分支>`，交叉审查用 detached worktree `../<项目>-worktrees/review-<分支>`。
- 审查：主控审查每个任务。
- 合并：审查通过后<本地合并进 main，再推送 / 开 PR>。
- 收尾记号：一件活合并完、worktree 和分支清干净之后，在 main 上补一条空提交（`git commit --allow-empty`），首行写「<前缀>: 」加一句话说明这件活是什么。只记真正落地的活；说好不合并、停在审查的不记。
- 开出来的 agent：清掉某个 worktree 时，把住在里面的那个一并关掉（它的工作目录没了，接不了新活）；其余的用户说关才关。
- 不要按项目名或路径批量杀进程（`pkill -f <项目>` 这类）：主控和别的 agent 的进程命令行里都带着项目名和工作目录，一条命令能把它们全杀掉。停自己起的服务用起的时候记下的 PID（`cmd & echo $!`），或者固定端口后 `lsof -ti:<端口> | xargs kill`。
```

## 2. 每一行管什么

| 行 | 作用 | 不写会怎样 |
|---|---|---|
| 第一行 | 开关：让主控知道「开始」就是要拆开派出去，并去加载 corral-dispatch | 主控多半自己动手写 |
| 被委派的不再往下派 | 防止一层套一层 | 任务文件模板里也有这句，是双保险 |
| 需求单照抄验收原话 | 用户说要加个任务时，主控按项目流程写需求单，那时不一定加载了分派技能；这一行让需求单也不被扩写 | 主控会把几条要求扩成十几个验收点，开发和审查照着逐条证明，活就变重 |
| 名字前缀、任务文件、worktree 位置 | 统一命名和存放位置 | 主控会问你一次 |
| 审查 | 主控审查每件活 | 技能里本来就是这样 |
| 合并 | 本地合并还是 PR、推不推送 | 主控会问你 |
| 收尾记号 | 一件活落地了在 git 里留个固定记号，`git log --grep` 一敲就是做完的清单 | 不写照样能跑；进度只能靠翻合并提交和交接文件看，没有机器认得的记号 |
| 关 agent | worktree 清掉时一并关掉住在里面的那个，其余默认不关 | 技能里本来就是这样 |
| 不按名字杀进程 | 防止误杀主控和并行的 agent | 任务文件模板里也有这句，是双保险。2026-09-20 真出过一次：一个 agent 想停自己起的服务，跑了 `pkill -f <项目名>`，把主控连同它的上下文一起杀了 |

**交给哪家、几档、要不要交叉审查都不写**：交给哪家由主控照技能第 3 节的分工表定；几档和交叉审查先问路由，路由拿不准再按技能里的分档表和第 6 节定。项目确实要不同时才写，比如「这个项目不用路由」（任务内容敏感、不想把摘要发给 TypeSafe），或者「这个项目只用 Codex」。

## 3. 其他准备

- **Claude Code 读的是 CLAUDE.md。** 项目里只有 AGENTS.md 时，建一个软链接 `ln -s AGENTS.md CLAUDE.md`，两家就读同一份。
- **第一次会弹信任框。** 新项目第一次开主控（Claude Code）、第一次开 Codex，都会问「是否信任这个目录」。agent 在 corral 里会一直停在「启动中」，要你运行 `corral attach <名字>` 去点，再按 Ctrl-] 断开。Codex 把信任记在主仓库目录上，所以同一个仓库以后的 worktree 应该不会再问（还没实测）。
- **开主控**：先 `corral start <项目>/main --cwd <仓库> -- claude`，再 `corral attach <项目>/main` 接进去，描述任务后说「开始」。
- **项目文档**：有背景、设计这类文档的，在 AGENTS.md 里列出来，主控写任务文件时会把它们放进「先读」。

## 4. 实测（2026-09-19）

测试项目的 AGENTS.md 按第 1 节写，技能装在项目级位置。用 sonnet 开主控，第一句话只写了两个小功能和「开始」，没提技能名，也没提「主控」。

- 主控的第一步就是加载 corral-dispatch，然后写了两份任务文件、建了两个 worktree。数字那件交给 Codex，文字那件交给 Claude Code，都按 AGENTS.md 用了轻档。
- 两件做完后，主控各审查一遍：重跑测试、核对改动范围、在任务文件末尾追加主控审查，然后本地合并。main 上 7 个测试全部通过，两个 agent 留着没关。
- 中途卡了两次信任框，一次是主控，一次是 Codex，都由人去点。
