# corral 设计

**corral**（畜栏）：给交互式 AI 编程 agent（Claude Code、Codex 等）用的极简托管基础设施。
每个 agent 关在自己的**栏位**里；调用方按名字打开它、往里塞话、查它的状态、等它答完、取回复；人随时可以从任何终端接进去看、点对话框、插话。

状态：**试验完成（2026-09-15），决定做；本文已按试验结论更新，下一步写正式版。** 试验清单、证据和每个设计选择的来龙去脉见 [SPIKE.md](SPIKE.md)。

---

## 1. 定位

- **是基础设施，不是流程工具。** corral 只提供机制；什么时候开谁、送什么话、看到空闲之后做什么，全由调用方（上层 harness、脚本、或者另一个 agent）决定。
- **不认识任何具体的上层工具。** 名字是调用方给的普通字符串（如 `demo/alice`），corral 不解释含义。代码、文档、测试里不出现任何具体流程的概念。
- **对外只有一个契约**：`corral` 命令、它的 JSON 输出、它的退出码。契约文档带版本号。调用方**不许读 corral 的内部文件**（元数据、事件文件、socket），内部格式随时可改。
- **保留 agent 自己的交互界面。** 不走无头模式，不用编辑器协议替代 agent 的终端界面。
- **零依赖**：只用 Python 标准库；不依赖 tmux、herdr 或任何现成的终端工具。

AI 编程的三样东西：agent 是租来的；harness 是调用方自己的、值得精雕；终端这一层 corral 拿回来，但**只求够用：送得进、看得见、挂不了**。

## 2. 职责：只管机制，不管策略

| corral 提供（机制） | 调用方自己决定（策略） |
|---|---|
| **打开**：用一个名字拉起一个 agent | 名字怎么起、什么时候打开谁 |
| **塞消息**：往某个 agent 送一段文字，并确认送到 | 该送什么话、送给谁 |
| **查找**：某个名字的 agent 在哪、还活着没有 | 找到之后做什么 |
| **状态**：working / idle / blocked / starting / 不存在 | 看到空闲之后做什么、什么时候叫醒谁 |
| **等待**：等某个 agent 这一轮结束 | 等完之后做什么 |
| **取回复**：某个 agent 上一轮的最后一条回复（干净文字） | 回复怎么用 |
| **接入**：让人进去看、点对话框、插话 | 拉起之后要不要自动弹出窗口、弹在哪 |
| **关闭**：让某个 agent 退出 | 什么时候关、关哪个 |

**判断越界的信号**：调用方改需求时要跟着改 corral；或者调用方的代码里出现 corral 内部文件的路径。任一出现，说明边界划错了。

## 3. 不重做 herdr，也不重做 tmux

herdr 是两套东西：常驻后台服务（工作区、标签、窗格、按屏幕识别 agent、通知、远程、worktree、更新）加终端里的前端（在一个窗口里画多个窗格，本质上是终端模拟器）。corral 两套都不重做。

| herdr 的能力 | corral |
|---|---|
| 前端：多窗格渲染、布局、标签、工作区 | 不做，交给用户自己的终端（Ghostty 等）；一个 agent 占一个标签或分屏 |
| 终端模拟：解析并维护每个窗格的画面 | 不做；`corral attach` 只原样转发字节，画面由用户的终端画 |
| 常驻服务持有所有窗格 | 没有中心服务；每个 agent 一个栏位，只持有自己的伪终端 |
| 按屏幕内容识别 agent 和状态 | 不做，改用 agent 自己的钩子 |
| 送 prompt 并等待 | 保留：`corral send`，以「收到输入」钩子为送达证据 |
| 查 agent 列表和状态 | 保留：`corral ls`、`corral status` |
| 读屏（渲染后的干净文字） | 不做；「正在做什么」从钩子事件得到（最近调用的工具、这一轮已跑多久）；回复从钩子或对话记录得到 |
| 通知、worktree、远程、更新渠道、配置热加载 | 不做 |

**稳定靠什么**：不解析 agent 输出（不会被某版 agent 界面变化搞坏）；没有中心进程（一个栏位出事只影响一个 agent）；栏位写好不改；命令跑完即退、状态在文件里；只用 Python 标准库。

## 4. 同类工具调研（2026-09-15）

| 类别 | 工具 | 做法 | 和 corral 的关系 |
|---|---|---|---|
| 终端层「每会话一个进程」 | dtach、abduco | 每个会话一个服务进程，在自己的伪终端里启动命令；会话按名字对应一个本机 socket（abduco 放在 `~/.abduco`） | 就是「栏位」的模型，久经验证；但不认识 agent，没有状态和送达确认 |
| agent 托管 | herdr | 中心服务 + 终端前端，带命令行和 socket 接口；进程名匹配 + 读屏启发式判断状态 | 和工作区界面绑在一起，是中心进程 |
| agent 托管 | subagent-cli | 一个常驻守护进程管所有会话，node-pty + 无头终端模拟，读屏状态机，网页终端接入 | 中心进程；项目很早期 |
| agent 托管 | agent-yes（命令 `cy`） | 每个 agent 一个独立进程，没有中心守护进程，靠共享文件登记；有 ls / tail / read / send / attach / stop；按正则匹配「就绪」画面 | 结构上最像 corral；但默认自动替 agent 回答「Yes」，带任务列表、问答等流程功能，依赖 Node 或 Bun |
| 协议标准 | ACP（Agent Client Protocol） | Zed、JetBrains 推的 JSON-RPC 标准，编辑器通过它驱动 agent | 用编辑器界面替代 agent 自己的终端界面 |

没有一个同时满足：保留 agent 自己的交互界面、没有中心进程、状态靠钩子而不是读屏、只做基础设施不带流程、零依赖。
状态判断最难通用：多数工具选读屏（零配置，但 agent 界面一改版就可能失灵）；钩子更可靠，但要给每家 agent 配置、还会碰到信任确认。

**只参考，不采用**：abduco 的源码（伪终端、socket、脱离终端的细节）；agent-yes 的文件登记设计。

来源：[abduco 手册](https://man.archlinux.org/man/abduco.1.en)、[abduco](https://github.com/martanne/abduco)、[subagent-cli](https://github.com/yejianfei/subagent-cli)、[agent-yes](https://github.com/snomiao/agent-yes)、[Herdr 文档](https://herdr.dev/docs/)、[ACP agents](https://agentclientprotocol.com/get-started/agents)

## 5. 结构：栏位 + 命令 + 内部文件

### 5.1 栏位（每个 agent 一个极小的进程，唯一常驻的东西）

- 持有这个 agent 的伪终端（Python `pty`），agent 是它的子进程。
- 脱离启动它的命令独立运行（新会话），不属于任何窗口，挂到系统进程名下。
- 只做字节级的事：转发接入者的输入输出、写入一段文字、调整终端尺寸、保留最近输出。**不解析 agent 的界面内容。**
- 顺带记几样终端层面的通用信息：
  - **最后一次输出的时间**；
  - agent 设置的**终端标题**（标准终端功能，不是某家 agent 的界面内容）；
  - agent 打开的**终端模式**（DEC 私有模式如粘贴模式、焦点上报、备用屏幕、鼠标，以及 kitty 键盘协议）：新窗口接入时先重放，否则新窗口不知道这些模式；
  - **最后一次人工按键的时间**：接入窗口里可打字的那个人最后一次按键的时间（`send` 据此避让，见 5.2）。**终端自动发出的回应不算人工按键**：焦点切入 / 切出（`ESC[I` / `ESC[O`）、光标位置报告、设备属性报告、OSC 查询的回答等，是 agent 打开了相应模式或发了查询后由终端自动回的，人只是切了一下窗口焦点也会产生。鼠标点击、滚轮算人工操作。
- agent 拿到**默认的信号处理和空的信号屏蔽**：「忽略」会随 exec 继承（Python 启动时忽略 SIGPIPE，栏位自己忽略 SIGHUP），而 shell 无法恢复启动时就被忽略的信号，不重置的话 agent 里的管道和挂断处理都会异常（M1 实测：不重置时 agent 收到 SIGPIPE、SIGHUP 都不退出）。
- 同一个 agent 的写入由栏位串行处理，两段文字不会交错。
- agent 退出：栏位记下退出码、删掉自己的 socket 后退出。
- **写好之后基本不改**：corral 升级时新版本只对之后打开的 agent 生效，正在跑的栏位不替换、不杀。栏位启动时一次性加载完所有要用的模块，之后不再从磁盘读 corral 的代码；和其他版本的配合见 5.4。

### 5.2 `corral` 命令（跑完就退出，不常驻；这就是对外契约）

| 命令 | 作用 |
|---|---|
| `corral start <名字> --cwd <目录> [--prompt <首句>] [--env K=V]… -- <agent 命令…>` | 拿文件锁防止同名 agent 被拉起两次，启动栏位，输出名字和实例编号。加 `--unique` 时把名字当前缀，自动补不重复的后缀（如 `demo/ask-3`）。`--prompt` 按 agent 种类作为启动参数交给 agent，由 agent 自己提交（新开的 agent 送第一句话只能走这里，见第 12 节）。环境见第 9 节 |
| `corral send <名字> <文字>` | 只在 idle 时送：连上栏位写入文字（多行用终端粘贴模式包起来），隔一小段再送回车；以「主会话的输入事件里的文字和送出的一致」确认送达。**不补发任何按键**，确认失败就以约定退出码报错。以下情况以约定退出码拒绝：状态不是 idle；最近 30 秒内接入窗口里有人按过键（调用方稍后重试，或用强制参数） |
| `corral keys <名字> <按键>` | 送原始按键（回车、Esc、方向键），用于回答对话框、打断。不看状态，后果由调用方负责 |
| `corral status <名字>` | 状态、实例编号、最后一次输出的时间、终端标题、最近一次调用的工具、这一轮开始的时间、最近一次输入的来源（`send` / 接入窗口里的人 / agent 自己）、接入人数、最后一次人工按键的时间 |
| `corral wait <名字> [--quiet N]` | 等到这一轮结束（idle 或 blocked），带超时；状态要稳定一小段才算（会话开始和输入事件可能相隔几十毫秒先后到）；输出结束时的状态。可选 `--quiet N`：**只在状态是 working 时**，连续 N 秒没有输出就返回，结果单独标明为 `stopped-quiet`，和真正收到回合结束（idle）区分开；N 由调用方给，corral 不设默认。blocked 由事件先判出，不受这个参数影响 |
| `corral reply <名字>` | 主会话上一轮的最后一条回复，干净文字 |
| `corral where <名字>` / `corral ls` | 定位、确认还活着；栏位已死的残留顺手清掉 |
| `corral read <名字>` | 最近若干行原始输出，去掉控制字符。没有终端模拟，agent 重绘时文字会乱，**只作排查用** |
| `corral attach <名字>` | 直接连栏位，原样转发输入输出。接入时先重放 agent 打开的终端模式，再触发一次终端尺寸变化让 agent 自己重绘；把名字写进窗口标题；按约定键（Ctrl-]）退出，agent 继续跑，退出时还原终端模式。**退出键要按键盘协议解析**：agent 打开 kitty 键盘协议后，终端发来的 Ctrl-] 是 `ESC[93;5u` 而不是单字节 |
| `corral attach --wait <名字>` | 名字还不存在时显示「等待某某出现」，一出现就自动接上；agent 退出后回到等待，下次出现再接上 |
| `corral stop <名字>` | 先用这种 agent 自己的退出方式，超时再依次发 SIGHUP、SIGTERM、SIGKILL；**等栏位真正退出才返回**。agent 自己脱离出去的后台进程不清 |

所有查询命令都有 JSON 输出；退出码写进契约文档。**所有命令**（不只是 `start`）发现自己在 Codex 沙箱里，都以同一个退出码拒绝并说明原因（沙箱里连不上栏位，否则会误报「不存在」）。

**idle 只表示「这一轮结束」**，不代表 agent 不会再动：agent 可能自己开新一轮（例：Claude Code 的后台命令结束后，自己注入一条通知作为输入）。调用方看 `status` 里的「最近一次输入的来源」判断要不要继续等。

### 5.3 内部文件（corral 私有，调用方不许读）

```
~/.corral/                     ← 0700；可用环境变量改位置
  demo/                        ← 0700
    alice/                     ← 0700；名字 demo/alice 就是这个路径
      lock                     ← 0600；栏位活着期间一直持有文件锁
      meta.json                ← 0600；实例编号、pid、cwd、agent 种类、启动命令、启动时间、协议版本
      sock                     ← 0600；栏位在这里监听；连得上 = 还活着
      hook.py                  ← 0600；start 时从 corral 复制过来的钩子脚本，钩子只运行这一份
      events                   ← 0600；钩子往这里追加（里面有送出去的原文和回复原文；agent 内部子会话也会写进来，按 session_id 区分）
      cursor                   ← 0600；命令侧读事件的进度和算好的状态快照，见下
      exit.json                ← 0600；agent 退出后记下退出码
      pen.log                  ← 0600；栏位自己的错误输出
    bob/  …
```

- `corral start demo/alice -- codex` 的过程：建目录并拿文件锁（同名不能再启动一个）→ 复制钩子脚本 → 起栏位，由栏位启动 codex，并把名字、实例编号、事件文件位置放进 codex 的环境变量 → 栏位写 meta.json、开始监听 sock。
- 之后任何命令找它，都是按名字算出路径、连 sock：连得上就是它；连不上说明栏位已死，清掉残留、报「不存在」。
- **权限**：目录 0700，文件和 sock 0600（事件文件里有送出去的原文）。创建时就设好，不依赖 umask。
- **macOS 上 Unix socket 路径不能超过 104 字节。** sock 就放在名字目录里；`start` 发现路径超长就拒绝并说明（名字太长或状态目录太深）。
- **钩子**：钩子命令是 `/usr/bin/python3 <该 agent 状态目录>/hook.py <事件>`，**不引用 corral 仓库里的文件，也不引用 start 时那个 Python**。否则 Python 被升级删除、corral 仓库被移动 / 切分支 / 更新，正在跑的 agent 的钩子会全部失效、状态卡住。`hook.py` 保持 Python 3.9 兼容，只用 `json`、`os`、`sys`、`time`，只往事件文件追加一行（带事件格式版本号、实例编号和状态计算需要的字段，不写工具的输入输出），不往标准输出写任何东西。`start` 先试跑一次 `/usr/bin/python3`（带超时），不能用就拒绝并说明（没装开发者工具的 Mac 上它是一个会弹安装窗口的占位程序）。
- **事件文件增量读**：长期运行的 agent 事件文件会越来越大，`status`、`wait`、`send`、`reply` 不整份重读。命令侧维护 `cursor`：记下实例编号、已读到的字节位置，以及读到这个位置为止算好的快照（主会话、状态、最近工具、这一轮开始时间、最近几次输入的文字摘要和时间、上一轮回复）。每次只从这个位置往后读，只消费到最后一个完整换行（钩子可能正写到一半）。实例编号变了或文件变短，就从头重算。多个命令同时读时，各自算完用原子替换写回；快照只取决于它记录的读到位置，旧快照覆盖了新快照也不会算错，下一个命令最多多读一段。会话开始和输入事件可能乱序到达，快照里暂存少量还认不出属于哪个会话的事件。

### 5.4 升级与兼容

栏位启动后不升级，钩子脚本在启动时复制了一份，所以新版 `corral` 命令一定会遇到旧版栏位和旧版钩子写的事件。

- **两个版本号**：栏位协议版本（栏位在握手应答和 meta.json 里报出）；事件格式版本（钩子写在每一行里）。
- **兼容规则（写进契约）**：新版命令至少兼容**上一个**协议版本的栏位和上一个事件格式版本；遇到更旧或更新（不认识）的版本，以专门的退出码拒绝，并说明是哪个版本、建议 `stop` 后重新 `start`。
- 协议只做加法：新增字段和操作，旧命令不认识的字段忽略；要删改语义就升协议版本。
- 测试里固定保存一份上一个协议版本的栏位实现，每次都用当前命令去操作它。

## 6. 身份：句柄和 agent 一起诞生

herdr 是先有窗格、后在里面启动 agent，只能事后猜哪个窗格跑着谁；窗格编号还会被复用，调用方要按工作目录找 agent、比对终端编号和会话编号，同一目录的两个 agent 只能靠名字区分。

corral 反过来：agent 由栏位启动，「谁是谁」在打开那一刻就写定。

| | herdr | corral |
|---|---|---|
| 句柄 | 窗格编号 | 名字 + 实例编号 |
| 身份怎么来 | 事后识别窗格里跑的是什么 | `corral start` 时由调用方给定名字，corral 发实例编号 |
| 怎么找到 | 按目录或名字搜索 | 按名字直接定位 |
| 同一目录跑两个 agent | 靠名字区分，会认错 | 名字不同就是两个栏位，不可能混 |
| agent 被换掉 | 比对终端编号和会话编号来防 | 再打开就是新的实例编号，调用方比对即可 |
| 关掉显示它的窗口 | 窗格没了，agent 也没了 | 什么都不影响，窗口只是观看者 |

- **agent 自己怎么知道自己是谁**：栏位启动 agent 时放进环境变量的名字和实例编号，agent 里运行的脚本会继承。
- **实例编号防什么**：同名 agent 退出后又被重新启动，名字相同、实例编号不同。调用方比对实例编号，就不会把发给旧 agent 的话塞给一个毫不知情的新对话。
- **只管用 `corral start` 启动的 agent。** 在终端里直接敲 `claude` 启动的，corral 看不见。

## 7. 终端有两层，agent 不绑定任何窗口

- **伪终端**：操作系统提供的一对字符设备。agent 从一头读键盘输入、往这一头写画面；谁拿着另一头，谁就能替它打字、看它的画面。agent 真正「跑在里面」的是这个。
- **终端窗口**（Ghostty 等）：只是显示器，把字节画成像素、把按键变成字节。

herdr 也从来没拿过终端软件的窗口句柄：它的窗格编号是它后台服务里某个伪终端的编号。corral 同理，句柄是名字。

```
herdr：   agent ⇄ 伪终端 ⇄ herdr 后台服务（窗格编号） ⇄ herdr 前端    ⇄ 窗口
corral：  agent ⇄ 伪终端 ⇄ 栏位（名字）              ⇄ corral attach ⇄ 窗口
```

右边那截随时可以断开、换个窗口再接。**给 agent 塞消息是经过栏位往伪终端写字节，完全不经过任何窗口。** 所以系统只记名字，不记窗口。

2026-09-15 的小实验：一个 Python 脚本调用一次 `pty.fork()`，子进程问「我的终端是哪个」得到 `/dev/ttys006`、「我连着终端吗」得到「是」，全程没有任何窗口。

## 8. 退出不影响运行：为什么成立

- **普通终端里关窗口为什么会带走程序**：窗口程序自己拿着伪终端的另一头；关窗口时这一头被关掉，操作系统给里面的程序发「终端挂断」信号，程序默认退出。
- **tmux、herdr 的办法**：伪终端的另一头由不属于窗口的后台进程拿着；窗口里跑的只是客户端。关窗口只死客户端。像远程桌面：关掉窗口，那台电脑上的程序照样跑。
- **corral**：拿着另一头的是栏位。栏位开新会话、脱离启动它的命令和窗口，挂到系统进程（macOS 上是 launchd）名下；启动它的程序清理自己名下的进程组时碰不到它。

```
关窗口之前：  agent ⇄ 伪终端 ⇄ 栏位 ⇄ corral attach ⇄ 窗口
关窗口之后：  agent ⇄ 伪终端 ⇄ 栏位                     （断开的只有右边）
再次接入：    agent ⇄ 伪终端 ⇄ 栏位 ⇄ corral attach ⇄ 另一个窗口
```

| 发生了什么 | agent 还在跑吗 |
|---|---|
| 关掉显示它的窗口，甚至退出整个终端软件 | 在 |
| attach 里按约定键退出 | 在 |
| 启动它的脚本或 `corral` 命令结束 | 在 |
| 升级 corral | 在（栏位不被替换） |
| agent 自己退出（比如输入 /exit） | 不在；栏位删掉 sock、记下退出码后退出 |
| 有人手动杀掉栏位进程 | 不在 |
| 电脑重启 | 不在（tmux、herdr 也一样） |

## 9. 沙箱与环境继承

栏位是调用 `corral start` 的那个进程启动的，所以它和它拉起的 agent 会继承调用者的环境变量、资源限制，**以及沙箱**。

**Codex 的沙箱默认开启。** 官方文档：macOS 上用系统自带的 Seatbelt，开箱即用；在 git 仓库里推荐「工作区可写 + 需要时请求批准」；沙箱作用于它运行的所有命令及其子进程；`--yolo` 是 `--dangerously-bypass-approvals-and-sandbox` 的别名，不用沙箱、不请求批准。

2026-09-15 本机实测（`codex sandbox -P :workspace -C <仓库> -- <命令>`，按默认「工作区可写」配置运行命令，不调用模型）：

| 在沙箱里做的事 | 结果 |
|---|---|
| 查看环境变量 | 有 `CODEX_SANDBOX=seatbelt`、`CODEX_SANDBOX_NETWORK_DISABLED=1` |
| 在仓库里写文件 | 允许 |
| 往家目录（仓库外）写文件 | **拒绝** |
| fork 两次、开新会话脱离后再写家目录 | **仍然拒绝**：脱离甩不掉沙箱 |
| 连本机其他工具的 Unix socket（以 `herdr agent list` 为例） | **拒绝** |

**对策**
1. **识别并拒绝**：任何 `corral` 命令发现环境里有 `CODEX_SANDBOX`，直接拒绝，说明「当前在 Codex 沙箱里，拉起的 agent 会被一起关进去，请用 --yolo 启动调用方」。试验实测：沙箱里栏位绑不上 socket，也连不上正在跑的栏位；不先识别的话，查询命令会误报「不存在」。
2. **从登录 shell 重建环境**：`corral start` 用最小环境（HOME、USER、LOGNAME、SHELL、TMPDIR、LANG，以及系统给的 SSH_AUTH_SOCK）启动用户的登录 shell，取一次它的环境，得到和用户自己新开终端敲命令时一致的环境：有用户在 shell 配置里给 agent 设的变量，PATH 也不带调用方临时加的目录，调用方的会话变量根本进不来。再兜底剥一遍会话变量（`CODEX_*`、`CORRAL_*`、agent 和其他终端工具的会话标识变量；`CODEX_HOME` 是用户配置目录，保留），重新设置名字、实例编号、事件文件位置；调用方可用 `--env K=V` 补充或覆盖。
   - 试验里的反例：只留白名单变量会丢掉用户 shell 配置里给 agent 的渲染开关；原样继承 PATH 会带进调用方 agent 会话临时加的一串目录。
   - 注意：agent 跑命令时自己也可能重读登录 shell（实测 Codex 如此），这只影响 agent 跑的命令；agent 进程本身的环境由 corral 决定。
   - shell 配置往外打印的内容用前后标记隔开，不影响取环境；10 秒内没取到就退回白名单环境，`start` 输出里带警告。
   - 代价：每次 `start` 多跑一次登录 shell（M2 实测本机 zsh 约 1.4 s）。

Claude Code 的 auto mode 是权限模式，不是系统沙箱；它可选的命令沙箱默认关闭。

## 10. 架构选择：每个 agent 一个栏位，不设中心服务（2026-09-15 定）

「常驻进程」拆成两件事来看：

1. **谁拿着伪终端**：决定 agent 会不会一挂全挂。
2. **谁负责把 agent 生出来**：决定 agent 继承谁的环境（环境变量、资源限制、沙箱）。

| 方案 | 谁拿伪终端 | 谁生 agent | 优点 | 缺点 |
|---|---|---|---|---|
| **A（选定）** | 每个 agent 一个栏位 | 调用者直接启动栏位 | 没有任何中心进程，最简单 | 继承调用者的环境和沙箱（第 9 节已有对策） |
| B 中心服务（tmux、herdr） | 一个服务拿所有 | 服务 | 环境干净统一；唯一登记表，等待时能主动推送 | 单点故障；升级要交接；登记表在内存里，重启要恢复 |
| C 混合 | 每个 agent 一个栏位 | 一个只负责「生」的常驻进程 | 环境干净；它挂了已在跑的 agent 不受影响 | 多一个常驻进程 |
| C′ 混合，不常驻 | 每个 agent 一个栏位 | launchd 按需拉起的「生」进程，生完就退 | 环境干净；平时无常驻进程 | 绑定 macOS（Linux 上是 systemd）；多一层实现 |

| | 一个服务管所有 | 每个 agent 一个栏位 |
|---|---|---|
| 服务出问题 | 所有 agent 一起没 | 只影响那一个 agent |
| 「谁是谁」这张表 | 在服务内存里 | 在磁盘上，一个 agent 一个目录 |
| 升级 | 全部重启，或做复杂的交接（herdr 专门有带交接的更新命令） | 新版本只用于之后启动的 agent |
| 代码复杂度 | 一个进程同时照看很多伪终端和客户端 | 一个栏位只照看一个伪终端 |
| 列出所有 agent | 问服务一次 | 扫一遍目录 |

代价：本机实测（Python 3.14，加载栏位要用的标准库模块后空闲）每个栏位约 16 MB 内存，空闲时阻塞等数据，不轮询。六个 agent 合计约 100 MB。

**结论**
- 「谁拿伪终端」坚持每个 agent 一个，这是稳定性的核心。B 在这一点上是倒退。
- 「谁生 agent」选 A；环境继承靠第 9 节的两条对策。
- 重新考虑的条件：需要调用方在 Codex 沙箱里也能正常使用 → 改 C′；`corral wait` 实测延迟或耗电不可接受 → 考虑 B（可能性很小：等待可以用系统的文件监听，不必轮询）。

## 11. 栏位之间不沟通，也不需要找对方

每个栏位只守住自己那个 agent 的伪终端，等别人来连。**跑来跑去的是一次次运行完就退出的 `corral` 命令，由调用方调用。**
比方：每个栏位是一户人家，门牌号就是路径，门上有投信口（sock）；邻居之间从不串门；要给谁传话就派一次 `corral send` 按门牌号去塞纸条；真正的工作内容放在公共文件里，纸条上只写「去看某某文件」。

例：agent A 请 agent B 看一份材料。

```
agent A（栏位 A 里）
  │ 1. 把材料写进 task.md ─────────────────────→ 【文件】
  │ 2. corral start demo/bob -- claude   → 建起栏位 B，里面启动 claude
  │ 3. corral send demo/bob "去读 task.md，把意见写进 answer.md"
  │      └→ 按路径连 B 的 sock → B 把字打进 claude
  │ 4. corral wait demo/bob（或调用方自己的后台进程等）
  ▼
agent B（栏位 B 里）
  │ 5. 读 task.md，写 answer.md ─────────────────→ 【文件】
  ▼
agent A
    6. 读 answer.md（或 corral reply demo/bob）
```

栏位 A 和栏位 B 从来没有互相连过。**找得到**靠三条：名字就是地址（调用方按自己的约定知道名字）；同一个用户、同一台机器看到的是同一个状态目录；连得上就在，连不上就是不在，由调用方决定要不要重新启动。

## 12. agent 适配

认识 Claude Code 和 Codex、给它们配钩子，是 corral 的基础设施能力。

以下是 2026-09-15 在 Claude Code 2.1.272、Codex 0.154 上实测的结论（证据见 SPIKE.md）。

**钩子事件**：会话开始、收到输入、调用工具前 / 后、弹出权限请求、回合结束；Claude Code 另有通知（权限提示、空闲提示），Codex 另有打断。栏位启动 agent 时带上身份和事件文件位置的环境变量，钩子据此往事件文件追加一行（带实例编号；钩子脚本怎么放、怎么运行、写哪些字段见 5.3）。钩子命令**不往标准输出写任何东西**（Claude Code 会把「收到输入」「会话开始」钩子的标准输出加进对话上下文）。两家的输入事件都带 `prompt` 原文，回合结束事件都带 `last_assistant_message`，`corral reply` 直接用，不读对话记录。

**只认主会话**：agent 内部的子会话会继承同一套钩子，写进同一个事件文件（实测：Codex 的记忆整理子 agent，session_id 不同、没有对话记录、工作目录在 Codex 自己的目录下）。主会话 = 最近一次「工作目录和栏位一致、并且带对话记录」的会话开始；状态、送达确认、取回复都只看这个 session_id 的事件。

**状态怎么算**（只看主会话）：没收到会话开始 → starting；会话开始（非压缩触发）或回合结束、打断 → idle；收到输入、调用工具 → working；弹出权限请求、权限提示通知 → blocked（直到下一次调用工具、收到输入或回合结束）。

**Claude Code**
- `--settings <JSON>` 按启动参数加钩子，**和用户全局设置里的钩子同时生效**（实测：用户的通知钩子和 corral 的钩子都记到了同一句输入）。
- 启动约 0.5 s 触发会话开始。
- 权限框、「向用户提问」框都会先触发权限请求事件 → blocked，不会被误当成空闲。
- **按 Esc 打断没有任何事件**，状态停在 working。可用信号是「最后一次输出的时间」：实测干活时（生成文字、跑 20 s 的工具）输出最长停顿不到 1 s（界面转圈一直刷新），打断后输出停住。`status` 报出这个时间；调用方用 `corral wait --quiet N` 等：working 时连续 N 秒没输出就返回 `stopped-quiet`（见 5.2）。
- 收到 SIGHUP 约 1 s 正常退出。
- 后台命令结束后会自己注入一条通知作为输入，开新一轮（见 5.2「idle 只表示这一轮结束」）。
- 首句：`claude … "<首句>"`。

**Codex**
- 钩子来源：系统层、托管层、用户层、项目层（仅受信任项目）、插件，以及启动参数 `-c`（Codex 把它当成单独一层）。所有来源一起运行：实测项目层 `hooks.json`、项目层 `config.toml` 的 `[[hooks.Stop]]` 和 `-c hooks.Stop=…` 同时触发，`-c` 不会顶掉同名配置。
- **加钩子的做法**：`-c 'hooks.<事件>=[{hooks=[{type="command",command="…"}]}]'` 加 `--dangerously-bypass-hook-trust`。只用 `-c` 时启动会弹「钩子需要审核」框，点「全部信任」会把哈希写进用户的 `config.toml`，违反「不动全局配置」；所以必须带跳过信任的参数，契约文档要说明原因。
- **会话开始事件要到第一次提交输入才触发**。启动后、第一句之前没有任何事件，状态一直是 starting，和「卡在信任框」分不出来，所以第一句话必须用 `corral start --prompt`（`codex … "<首句>"`）。实测启动后很快用按键送首句，文字进了输入框但回车没提交。
- 第一次提交时，会话开始和输入事件相隔几十毫秒先后到，`wait` 要求状态稳定一小段才返回。
- 按 Esc 打断有专门的 `Interrupt` 事件，0.1 s 内到。
- **不理 SIGHUP**（空闲时和信任框里都一样），`stop` 要用 Codex 自己的退出方式。
- 信任：全局信任 `/` 对子目录不生效；`-c 'projects."…".trust_level=…'` 覆盖无效，照样弹信任框。

**不认识的 agent**：也能打开和接入，状态报「未知」。

### 已知难点：试验结论

1. **启动时的信任对话框，钩子看不见。** 两家弹框期间都没有事件，状态停在 starting，调用方用「starting 超过 N 秒」判断启动未完成。Claude Code 实测在 `/tmp` 下的普通新目录不弹、在新建的 git 仓库里弹，Codex 在不在信任列表里的目录弹。corral 不替人点。
2. **人按 Esc 打断。** Codex 有打断事件；Claude Code 没有，靠「最后一次输出的时间」，实测可靠；调用方用 `wait --quiet N`，结果标为 `stopped-quiet`。
3. **弹框的覆盖面。** Claude Code 的权限框、提问框都有权限请求事件。Codex 在 `--yolo` 下不弹审批，没测。
4. **「正在做什么」只能从钩子得到**：最近一次调用的工具名、这一轮开始的时间，够用。
5. **Codex 钩子信任**：必须用跳过信任的参数，见上。
6. **（试验新发现）送进去的字节会被 agent 界面按当时的画面解释。** 实测：界面开着「选模型」菜单时，送话的回车把选择写进了用户全局设置。所以 `send` 只在 idle 时送、不补发按键、有人刚在接入窗口按过键时避让（见 5.2）；`keys` 不设防，由调用方负责。

## 13. 使用场景

### 13.1 临时委派（会大量使用）

人对一个 agent 说「开一个 Claude Code，把上面的想法交给它看一下」：

```
agent（在自己的 shell 里）
  1. corral start demo/ask --unique --cwd <仓库> --prompt "请看一下这个想法：……" -- claude
                                                              → 得到名字 demo/ask-3，第一句由 agent 自己提交
  2. corral wait  demo/ask-3                                  → 等它这一轮答完
  3. corral reply demo/ask-3                                  → 拿到干净的回复文字
  4. 把回复整理后告诉人；需要追问：corral send demo/ask-3 "……"，再回到第 2 步
  5. 用完：corral stop demo/ask-3（或留着以后接着问）
```

试验里两个方向（Codex 委派给 Claude Code、Claude Code 委派给 Codex）都由真实 agent 自己跑通，回复里的多段文字、代码块和 agent 原文逐字一致。

- 两种起名方式：固定名字（接着上次的对话问）；`--unique`（每次一个干净的新对话，可以同时开好几个）。
- 人怎么看：在旁边预先开一个分屏挂 `corral attach --wait demo/ask`（固定名字时每次都自动出现）。
- 清理：临时 agent 不会自己退出，用完 `corral stop`；`corral ls` 看还有哪些开着。
- **不支持位置说法**（「交给右侧那个」）：corral 不管窗口布局，只认名字；只有一个别的 agent 在跑时，调用方可以用 `corral ls` 自己认出来。

### 13.2 在哪看由人决定

- 人自己启动的 agent：在某个终端标签里运行 `corral start …`，启动完直接接入当前标签。
- 调用方在后台启动的 agent：默认不出现在任何窗口里；想看就在任意标签或分屏里 `corral attach`。
- 想让某个 agent「自动出现在旁边」：预先开一个分屏挂 `corral attach --wait <名字>`，一出现就接上。开分屏由人或调用方用自己终端的能力做，corral 不做；例：Ghostty 1.3 可用 AppleScript `split … with configuration {command:"corral attach --wait <名字>"}` 在当前窗口开分屏（试验已验证）。
- 多个窗口接同一个 agent：只允许一个窗口打字，其余只读；终端尺寸跟着能打字的那个走。
- 人在接入窗口里看着时，调用方照常 `send`；人最近 30 秒内按过键，`send` 会避让（见 5.2）。

### 13.3 给 agent 用的使用说明

corral 自带一份给 agent 看的使用说明，只讲命令怎么用。任何 agent 读了它，就能自己开别的 agent、送话、等回复、取回复。

## 14. 设计约束

- **栏位不能挂**：除栏位外没有任何常驻进程；升级不杀正在跑的栏位；正在跑的 agent 不依赖 corral 仓库里的文件和某个特定版本的 Python（见 5.3 钩子、5.4）。
- **只听本机**：状态目录 0700，sock 和所有内部文件 0600，放在用户自己的目录下。
- **不摆窗口布局**：没人接入时伪终端用默认尺寸，有人接入就换成接入窗口的尺寸。
- **不动全局配置**：钩子只随栏位启动的那个 agent 生效，并且和用户已有的全局钩子共存。corral 自己送进 agent 的字节也不能导致 agent 改配置（见第 12 节难点 6）。

## 15. 不做

- 不理解任何流程，不转发内容，不管队列和轮次，不摆窗口布局。
- 不支持位置说法，只认名字；不管理不是用 `corral start` 启动的 agent。
- 不做前端，不做常驻中心服务。
- 不做终端模拟、读屏、多窗格布局、主题、会话恢复。
- 不做网页里的终端。
- 不做 Windows、远程机器支持。
- 不自动替 agent 回答任何对话框。
