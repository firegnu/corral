## 背景：corral 之上还差什么

corral 只做了托管 agent 的后台那一小块：栏位、命令、钩子、接入。原来由终端多路复用工具的前端提供的体验，corral 有意没做。对照下来，四样东西里有三样不用写前端就能拿回来，第四样明确不做：

| 前端给的体验 | 不写前端怎么拿 | 归属 |
|---|---|---|
| 侧边栏看谁在忙、谁卡住、在做什么 | 一个小看板轮询 `corral ls` 和 `corral status`，在终端里画个列表 | R1 |
| 某个 agent 一启动就自动出现在旁边 | 分屏挂 `corral attach --wait`；或用终端软件自己的脚本能力开分屏 | 已有，不另做 |
| 做完、卡住的提醒 | 一个小守护进程盯 `status` 的变化，发系统通知 | R2 |
| 多窗格布局、会话恢复 | 需要自己写终端模拟器 | **不做**（DESIGN 第 15 节），交给 Ghostty 等终端软件 |

前三样加起来估计几百行，而且都只读 corral 的公开输出。

**边界**：R1、R2 都是建在 corral 契约之上的配套工具，不进 corral 核心。它们只用 `corral` 命令的 JSON 输出，不读状态目录里的任何文件；corral 核心不为它们加任何字段以外的东西。DESIGN 第 5 节「不做」里写的「通知」指的是核心不做，配套工具做不算违反；动手时把这句在 DESIGN 里说清。

## R1 看板

### 目标

一个终端里的只读列表：每个 agent 一行，名字、种类、状态、正在用的工具、这一轮跑了多久、最后输出距今、有没有人接着、卡住了没。每秒左右刷新一次。不做交互，看完 Ctrl-C 退出。

### 怎么做

- 单文件，标准库，放在 corral 仓库的 `bin/` 或另起一个小仓库，二选一在动手时定。
- 数据只来自 `corral ls` 和 `corral status <名字>`；名字列表变化时增删行。
- 卡住的判定（`blocked`、`starting` 超过多久、`working` 但很久没输出）是看板自己的策略，阈值写在看板的参数里，不进 corral。
- 显示用最朴素的终端重绘（清屏加整屏输出），不引入任何终端库。

### 现状（2026-09-17）

- 手工测试时写的测试工具，在 side project 里用着顺手，搬进本仓库：`tools/board`。不是 `corral` 的子命令，不进契约，不引用 corral 的内部代码，只调用本仓库的 `bin/corral`。
- 每个 agent 一行：名字、种类、实例编号前 6 位、状态、正在做（`working` / `blocked` 时显示最近的工具和这一轮已跑多久）、多久没输出、接入窗口数、最近一次输入的来源、终端标题。默认 3 秒刷新；`--prefix` 只看某个前缀，`--once` 只打印一次，`--every` 改刷新间隔。
- 2026-09-18 随 R3 升级成面板：`blocked` 的行标红；`starting` 超时、`working` 但很久没输出标黄色 `?`，阈值是面板参数。
- 有测试 `tests/test_board.py`：空列表、状态和正在用的工具、前缀过滤、只读。

### 怎么算成功

- side project 日常开着它，一周内没有为了看 agent 状态回去开别的工具。
- 状态和实际一致：agent 卡住时看板在 5 秒内标出来。

### 止损点

- 动手两天没跑起来，或者跑起来后仍然更愿意直接 `corral attach` 一个个看：停，记下原因。
- 发现需要 corral 加公开字段以外的东西才能做：先回头看契约，不许读内部文件。

## R2 通知守护

### 目标

一个后台小进程，轮询所有 agent 的状态，出现下面几种变化时发一条系统通知，正文里带接入命令：

- 变成 `blocked`（权限框、提问框）。
- `starting` 超过阈值（多半卡在启动对话框）。
- 从 `working` 变成 `idle` 且最近一次输入来源是 `send`（别的 agent 交的活做完了）。
- 退出（`corral ls` 里消失，`status` 报退出信息）。

### 怎么做

- 单文件，标准库；通知用系统自带的命令（macOS 的 `osascript`），不装依赖。
- 每个 agent 记上一次看到的状态，只在变化时发，同一状态不重复发。
- 想常驻就由人自己用 launchd 挂起来；corral 不安装、不管理它。

### 怎么算成功

- side project 里 agent 卡住时，人不在盯着也能在一分钟内知道。
- 一天的通知数量在能忍的范围内，没有反复刷屏。

### 止损点

- 通知太吵、关掉不看：停，只保留 R1。
- 需要 corral 内部文件或新钩子才能做：同 R1，先修边界。

## R3 管理面板

### 目标

把 R1 的只读看板扩成一个终端里的管理程序：列表还是那张状态表，但能选中某个 agent 直接操作，不用再切到别的终端敲命令。

### 边界

- **外围工具，不进 corral 内核**。和 R1、R2 一样只调用 `corral` 的公开命令，不读状态目录，不引用内核代码，不是 `corral` 的子命令。
- **不嵌入 agent 的画面**。在面板里分出一块实时显示 agent 界面，需要终端模拟，这是 DESIGN 第 15 节明确不做的。要看 agent，就把整个终端让给 `corral attach`，断开后回到面板。
- 只用 Python 标准库；界面用标准库自带的 curses，支持键盘和鼠标点击。

### 功能按「需不需要动内核」分三类

**现有命令就能做**

| 操作 | 用的命令 |
|---|---|
| 状态列表，卡住的行高亮 | `ls`、`status`；阈值是面板自己的参数 |
| 选中后接入：面板让出终端，按 Ctrl-] 断开后回到面板 | `attach` |
| 在新的终端分屏或窗口里接入，面板留在原处 | 终端软件自己的脚本能力加 `attach`；只对支持的终端软件提供，属于可选 |
| 看上一轮回复、看输出尾部 | `reply`、`read` |
| 送一句话、按 Esc 打断 | `send`、`keys` |
| 关掉，带确认 | `stop` |
| 按已有模板开一个新 agent | `start` |

**需要内核新能力，做到这一步时先按 DESIGN 第 16 节评估**

- **把别人的接入窗口踢掉**（你说的「unattach」）。现在只有接入的那个窗口自己能按 Ctrl-] 断开，没有命令能从外面断开别的窗口。要做就得在栏位里加一个操作，属于高风险层。先确认是不是真需要：多数情况下，关掉那个窗口就够了。

**不做**

- 在面板里实时显示 agent 的界面、多个 agent 并排显示：需要终端模拟。
- 替 agent 回答权限框或提问框：和 corral 的规矩一致，面板只负责把人带进 attach。

### 怎么算成功

- side project 里一天下来，看状态、接入、送话、关掉这些事都在面板里完成，基本不用再手敲 corral 命令。
- 从面板接入再回来，终端模式都能还原干净，面板显示不乱。

### 止损点

- 发现离不开「在面板里直接看 agent 画面」：停下，这条路需要终端模拟，回到「board 加 attach 分开用」。
- 为了面板不得不给内核加第二个以上的新能力：停下，重新评估边界。

### 决定和现状（2026-09-18）

起因：agent 一多，每次看某一个都要手敲 `corral attach`；而且看的时候不能把看板冲掉。

- **升级 `tools/board`，不另起工具，不进内核**：corral 一行没改，只调用公开命令 `ls`、`status`、`reply`、`attach`、`stop`。
- **形式选终端程序，不做网页**：网页里要接入 agent 只能做网页终端（DESIGN 第 15 节不做），而且本地要开一个能给 agent 送话的服务，安全面大。
- **布局：面板加显示器，人自己分屏**。人把终端分成左右两格，左格运行 `tools/board`（面板），右格运行 `tools/board --viewer`（显示器）。面板里回车或鼠标点一行，显示器就在右格里替人运行 `corral attach`；换人时先断开当前的，被断开的 agent 继续跑；断开或 agent 退出后右格回到空闲画面。两边通过 board 自己的临时目录（`$TMPDIR/corral-board-<uid>/`）里的小文件传话。
- **为什么不让面板自己开分屏**：本机只有 Ghostty 能被脚本控制（AppleScript）；kitty 要改全局配置才能远程控制；Metalterm 没有脚本接口。人手动分一次屏，就不依赖任何终端软件。代价：点完 agent 要再点一下右格才能打字。
- **换人怎么断开**：显示器给 `corral attach` 发 SIGINT，attach 现有的清理代码会还原终端（测试里核对了还原序列），显示器再整屏复位兜底。这是 attach 现有的行为，契约没写。
- **第一版的操作**：接入（回车 / 点击）、看上一轮回复、关掉（`x` 再按 `y`）。没做：送话、打断、按模板新开、自动把焦点切到右格、踢掉别人的接入窗口。
- 测试：`tests/test_board.py` 新增 8 条（切换、点击、断开、agent 退出、关掉要确认、回复、没开显示器时的提示、显示器不执行启动前的旧指令、只能开一个显示器）。人在 Ghostty 里用假 agent 试过，反馈正常。
- **用了一天后的两处调整**：一是已经在别处接入的 agent，右格接进去是只读的，画面尺寸又跟着先接入的窗口走，显示会乱；这是 corral 的限制（不做终端模拟），面板改成不接，提示先在那边断开，人决定 corral 启动的都从面板看。二是界面太素，按人确认过的预览上色：标题栏和底栏深灰底，选中行深蓝底（不再用反色），状态列按状态上色，行首 `!` 标卡住、`▶` 标右格正在显示，在别处接入的标紫，次要列调暗。只用终端标准色，256 色以下的终端退回反色。
- **第三批（同日）**：做完一轮标 `●` 直到看过（看「这一轮开始的时间」有没有变，两次刷新之间跑完的短回合也抓得到），可选响铃，退出时底栏提示；疑似卡住标 `?`；目录列（来自 `corral ls` 的 `cwd`）；按前缀分组；`s` 切换按状态排；窄屏按先后藏列；回复区简单渲染 Markdown；在干活的行转圈；「无输出」按时长变色。人明确不要在面板里送话、打断、按模板新开（面板只看不操作，`x` 关掉保留）。「上一轮回复」下面加 diff 区的想法待讨论：面板只能看到工作目录里未提交的改动，分不清是哪个 agent 改的。

**边界：出现下面这些想法，就是在重做 DESIGN 第 3 节说的 herdr 前端，停下**

- 让面板自动分屏、摆布局、记住布局。
- 一格里同时显示多个 agent 的画面。
- 让显示器识别 agent 画面上的内容。
- 让面板常驻，关了终端还在。

## R4 适配 pi

**完成情况（2026-09-17）**：按下面的调查结论实现，事件格式、`events.py`、`hook.py`、栏位、协议都没改。假 agent 测 corral 这边的判定，bun 跑扩展的映射和格式一致性，真实 pi 验收：首句、送话确认、多行、工具、Esc 打断（0.1 s 回到 idle）、SIGHUP 停止（0.2 s）、当被委派方被 `send --after` 等待、当委派方用 `send --after` 被提醒。未实测：真实扩展弹框时的 blocked、项目信任提示、人手动 attach 的体验。验收时发现用户 pi 全局扩展里残留的一个扩展调用已删除的程序、让 pi 启动即崩，已由人决定清理，和 corral 无关。


### 调查结论（2026-09-17，pi 0.85.1）

可以接，条件基本齐全。只看了帮助信息和随包文档，没有实际跑过。

| corral 需要 | pi 怎么提供 |
|---|---|
| 只给这一个进程挂钩子，不改全局配置 | `--extension <文件>` 按启动参数加载扩展，和用户自己的扩展共存 |
| 会话开始 | `session_start`：会话编号、会话文件、工作目录 |
| 收到输入并带原文 | `before_agent_start`：用户输入原文 |
| 正在用哪个工具 | `tool_execution_start` / `tool_execution_end`，只通知，不影响执行 |
| 这一轮彻底结束，带回复原文 | `agent_settled`（不会再自动继续）；回复原文取自 `agent_end` 带的消息 |
| 卡住等人 | `ui_prompt_start` / `ui_prompt_end` |
| 退出 | `session_shutdown`；Ctrl-C、SIGHUP、SIGTERM 都触发，`stop` 发 SIGHUP 即可 |
| 第一句话从启动参数带进去 | `pi "<第一句>"`，交互模式 |

没有自带权限框和子 agent。

### 要动的地方

- 新增：`agents/pi.py` 适配器；一个 TypeScript 钩子扩展，把 pi 事件翻译成现有事件名写进事件文件；对应测试和假 pi agent。
- 修改：`agents/__init__.py` 注册；`spawn.py` 从「固定复制 hook.py」改成「按适配器复制各自的钩子文件」；内部文件清单加新文件名；`pyproject.toml` 包数据。
- 文档：CONTRACT 的 agent 种类、`--prompt` 支持范围、保留名字；DESIGN 第 12 节；skill 和使用说明。
- 不动：栏位、协议、`hook.py`、事件格式版本。
- **`events.py` 尽量不改**：它是所有命令判定状态共用的，改了立即影响正在跑的 Claude Code 和 Codex。映射：`session_start` → SessionStart，`before_agent_start` → UserPromptSubmit，工具事件 → PreToolUse / PostToolUse，`ui_prompt_start` → 权限框类的 Notification，`agent_settled` → Stop，`session_shutdown` → SessionEnd。`ui_prompt_end` 没有现成的「解除卡住」事件可映射，实测后如果确实要改 `events.py`，单独按 DESIGN 第 16 节评估。

### 动手前要人拍板

1. 仓库里第一次出现非 Python 文件。不增加依赖，但要和「只用 Python 标准库」对口径。
2. 扩展直接写事件文件（顺序可靠，格式在 TypeScript 里再写一份，用测试保证一致），还是每个事件调用 `hook.py`（格式一份，异步调用时顺序可能乱）。倾向前者。
3. 扩展本身的测试：假 agent 跑不了 TypeScript，只能测 corral 这边的判定；扩展本身靠真实 pi 验证，或在有 node 的机器上额外测。

### 要实测

- 按 Esc 打断后 `agent_settled` 是否照常触发。不触发就和 Claude Code 一样，只能靠 `wait --quiet` 兜底。
- 目录里有 `.pi` 或 `.agents/skills` 时的项目信任提示。
- 真实 pi 跑一遍委派、送话确认、`send --after`；委派方仍用 sonnet。

### 止损点

- 映射不干净，必须给 `events.py` 加 pi 专用的判定才能用：停下评估，不为一家 agent 让共用的状态判定变复杂。

## R5 适配 amp

### 调查结论（2026-09-17，amp 2026-09-17 构建）

**事件够用，但现在接不了，卡在插件的加载方式。**

| corral 需要 | amp 插件提供 |
|---|---|
| 会话开始 | `session.start` |
| 收到输入并带原文 | `agent.start` |
| 工具 | `tool.call` / `tool.result` |
| 这一轮结束并带回复 | `agent.end`：done / error / cancelled，加本轮消息 |
| 卡住等批准 | 当前会话状态流里的 `awaiting-approval` |
| 子会话 | 插件收到本进程所有会话的事件，要按父会话过滤 |

**卡住的原因**：插件只能从个人设置、工作区设置、项目 `.amp/plugins/`、全局 `~/.config/amp/plugins/` 加载。官方文档确认没有命令行参数或环境变量能按一次启动加载任意路径的插件。放项目目录等于往用户仓库里写文件，放全局目录等于改全局配置，都违反 corral 的规矩。改 `XDG_CONFIG_HOME` 能绕过去，但 agent 里跑的所有命令都会继承它，副作用太大，不采用。

**另外的问题**

- 第一句话没法从启动参数带进去：交互模式只支持管道输入，而 corral 里 agent 的输入是终端。
- `tool.call` 的处理函数必须返回一个决定，挂上它可能绕过 amp 自己的权限规则；要确认有没有只观察、不表态的写法。
- 会话默认存在 Amp 服务器上，涉及隐私的项目要注意。

### 什么时候再看

- amp 提供按启动参数加载插件；或者
- 人决定接受一个例外：像 `install-skills` 一样经人确认后装一个全局插件，只在检测到 corral 的环境变量时生效。这要先改 DESIGN 第 14 节「不动全局配置」。

## R6 上游 agent 升级后的真实冒烟

### 为什么

corral 的状态、送达确认、回复全靠各家 agent 的钩子事件。Claude Code、Codex、pi 都更新得很快，事件名、字段、触发时机一变，适配就可能静默失效：不报错，只是状态卡住、送达确认不上、回复取不到。单元测试用的是假 agent，发现不了这类问题。

### 做什么

- 冒烟脚本 `tools/smoke`（2026-09-17 已完成），配套工具，不进内核。用法：`tools/smoke [--agents claude,codex,pi,omp] [--no-delegator]`，默认四家都跑，一次约 8 分钟，退出码 0 表示全部通过。用单独的短路径状态目录，不碰用户正在用的 agent，用完清理。
- 每家 agent 跑同一组检查，只核对机制，不核对模型回答的内容：
  - `--prompt` 启动后到 idle，`reply` 取得到回复；
  - 多行 `send` 确认送达；
  - 调用一次工具，看到 working 和工具名，结束回到 idle；
  - Esc 打断：让 agent 在前台跑一条长命令（`ping -c 60 127.0.0.1`；Claude Code 会拒绝在前台跑长时间的 `sleep`，还可能把它放到后台，那样就没东西可打断），按 Esc 前再确认还在干活。Codex、pi、omp 回到 idle，Claude Code 用 `wait --quiet` 得到 stopped-quiet；
  - `stop` 按这家的方式正常退出；
  - 当委派方：用 `send --after` 交出任务，对方做完后被提醒。
- 模型用便宜的：Claude Code 用 sonnet，委派测试里被开出来的一方用 haiku；Codex 用便宜档；pi、omp 用各自的默认模型；omp 带 `--approval-mode yolo`。
- 工作目录：Claude Code、pi、omp 用 `/tmp` 下的临时目录，不在真实项目里跑，免得 agent 往项目里写记忆；Codex 只信任列表里的目录，用家目录。
- 输出一张表：每家 agent 的版本号、每项检查通过与否。结果连同版本号记进本文档下方的「冒烟记录」。

### 什么时候跑

- `claude --version`、`codex --version`、`pi --version` 任何一个和上次冒烟记录里的版本不同；
- 使用中发现状态卡住、送达确认失败、取不到回复，先跑一遍冒烟，分清是上游变了还是 corral 的问题；
- corral 内核有改动合回 main 之前。

### 止损点

- 模型回答不稳定导致检查时过时不过：只核对事件和状态，不核对回答内容；还不稳就减少检查项，不为了冒烟改内核。

## R7 适配 omp

**完成情况（2026-09-17，omp 18.2.2）**：和 pi 一样用 `--extension` 加载钩子扩展 `hook_omp.ts`，单独一份。omp 没有 `agent_settled`，回合结束由扩展从 `agent_end` 判断：`willContinue` 为真不算、可重试的出错多等 2.5 s、其余去抖 250 ms，期间收到新一轮就取消；审批用 `tool_approval_requested/resolved`，提问工具 `ask` 也算等人；只写有界面的主会话。`events.py`、`hook.py`、事件格式、栏位、协议都没改。真实 omp 验收：首句、送话确认、工具、Esc（0.4 s）、SIGHUP 停止（0.1 s）、当委派方用 `send --after` 被提醒。未实测：真实审批框、自动重试。
