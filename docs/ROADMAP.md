# 路线图

启动于 2026-09-16。只放「要加机制」的大事；小修小补照常走提交，不进这里。

每项都有**前置**和**止损点**：前置没到不动手，到点没达到成功标准就停下、记下原因。

| 编号 | 事项 | 状态 | 前置 |
|---|---|---|---|
| R1 | 看板：终端里看所有 agent 在干什么 | 第一版已落地（2026-09-17），观察中 | 在 side project 里用过一段时间，确认最想念的是「一眼看到状态」 |
| R2 | 通知守护：agent 卡住或做完时发系统通知 | 未开始 | R1 之后，或独立于 R1，看实际缺哪个 |
| R3 | 管理面板：在一个终端程序里既看状态又能操作 agent | 未开始，只登记 | R1 在 side project 里用过一段时间，记下最常做的操作 |

---

## 背景：corral 之上还差什么

corral 只做了托管 agent 的后台那一小块：栏位、命令、钩子、接入。原来由终端多路复用工具的前端提供的体验，corral 有意没做。对照下来，四样东西里有三样不用写前端就能拿回来，第四样明确不做：

| 前端给的体验 | 不写前端怎么拿 | 归属 |
|---|---|---|
| 侧边栏看谁在忙、谁卡住、在做什么 | 一个小看板轮询 `corral ls` 和 `corral status`，在终端里画个列表 | R1 |
| 某个 agent 一启动就自动出现在旁边 | 分屏挂 `corral attach --wait`；或用终端软件自己的脚本能力开分屏 | 已有，不另做 |
| 做完、卡住的提醒 | 一个小守护进程盯 `status` 的变化，发系统通知 | R2 |
| 多窗格布局、会话恢复 | 需要自己写终端模拟器 | **不做**（DESIGN 第 15 节），交给 Ghostty 等终端软件 |

前三样加起来估计几百行，而且都只读 corral 的公开输出。

**边界**：R1、R2 都是建在 corral 契约之上的配套工具，不进 corral 核心。它们只用 `corral` 命令的 JSON 输出，不读状态目录里的任何文件；corral 核心不为它们加任何字段以外的东西。DESIGN 第 5 节「不做」里写的「通知」指的是核心不做，配套工具做不算违反；动手时把这句在 DESIGN 里说清。

## R1 看板

### 目标

一个终端里的只读列表：每个 agent 一行，名字、种类、状态、正在用的工具、这一轮跑了多久、最后输出距今、有没有人接着、卡住了没。每秒左右刷新一次。不做交互，看完 Ctrl-C 退出。

### 怎么做

- 单文件，标准库，放在 corral 仓库的 `bin/` 或另起一个小仓库，二选一在动手时定。
- 数据只来自 `corral ls` 和 `corral status <名字>`；名字列表变化时增删行。
- 卡住的判定（`blocked`、`starting` 超过多久、`working` 但很久没输出）是看板自己的策略，阈值写在看板的参数里，不进 corral。
- 显示用最朴素的终端重绘（清屏加整屏输出），不引入任何终端库。

### 现状（2026-09-17）

- 手工测试时写的测试工具，在 side project 里用着顺手，搬进本仓库：`tools/board`。不是 `corral` 的子命令，不进契约，不引用 corral 的内部代码，只调用本仓库的 `bin/corral`。
- 每个 agent 一行：名字、种类、实例编号前 6 位、状态、正在做（`working` / `blocked` 时显示最近的工具和这一轮已跑多久）、多久没输出、接入窗口数、最近一次输入的来源、终端标题。默认 3 秒刷新；`--prefix` 只看某个前缀，`--once` 只打印一次，`--every` 改刷新间隔。
- 还没做：卡住的阈值判定和高亮。现在只是把状态和「多久没输出」列出来，由人自己看。
- 有测试 `tests/test_board.py`：空列表、状态和正在用的工具、前缀过滤、只读。

### 怎么算成功

- side project 日常开着它，一周内没有为了看 agent 状态回去开别的工具。
- 状态和实际一致：agent 卡住时看板在 5 秒内标出来。

### 止损点

- 动手两天没跑起来，或者跑起来后仍然更愿意直接 `corral attach` 一个个看：停，记下原因。
- 发现需要 corral 加公开字段以外的东西才能做：先回头看契约，不许读内部文件。

## R2 通知守护

### 目标

一个后台小进程，轮询所有 agent 的状态，出现下面几种变化时发一条系统通知，正文里带接入命令：

- 变成 `blocked`（权限框、提问框）。
- `starting` 超过阈值（多半卡在启动对话框）。
- 从 `working` 变成 `idle` 且最近一次输入来源是 `send`（别的 agent 交的活做完了）。
- 退出（`corral ls` 里消失，`status` 报退出信息）。

### 怎么做

- 单文件，标准库；通知用系统自带的命令（macOS 的 `osascript`），不装依赖。
- 每个 agent 记上一次看到的状态，只在变化时发，同一状态不重复发。
- 想常驻就由人自己用 launchd 挂起来；corral 不安装、不管理它。

### 怎么算成功

- side project 里 agent 卡住时，人不在盯着也能在一分钟内知道。
- 一天的通知数量在能忍的范围内，没有反复刷屏。

### 止损点

- 通知太吵、关掉不看：停，只保留 R1。
- 需要 corral 内部文件或新钩子才能做：同 R1，先修边界。

## R3 管理面板

### 目标

把 R1 的只读看板扩成一个终端里的管理程序：列表还是那张状态表，但能选中某个 agent 直接操作，不用再切到别的终端敲命令。

### 边界

- **外围工具，不进 corral 内核**。和 R1、R2 一样只调用 `corral` 的公开命令，不读状态目录，不引用内核代码，不是 `corral` 的子命令。
- **不嵌入 agent 的画面**。在面板里分出一块实时显示 agent 界面，需要终端模拟，这是 DESIGN 第 15 节明确不做的。要看 agent，就把整个终端让给 `corral attach`，断开后回到面板。
- 只用 Python 标准库；界面用标准库自带的 curses，支持键盘和鼠标点击。

### 功能按「需不需要动内核」分三类

**现有命令就能做**

| 操作 | 用的命令 |
|---|---|
| 状态列表，卡住的行高亮 | `ls`、`status`；阈值是面板自己的参数 |
| 选中后接入：面板让出终端，按 Ctrl-] 断开后回到面板 | `attach` |
| 在新的终端分屏或窗口里接入，面板留在原处 | 终端软件自己的脚本能力加 `attach`；只对支持的终端软件提供，属于可选 |
| 看上一轮回复、看输出尾部 | `reply`、`read` |
| 送一句话、按 Esc 打断 | `send`、`keys` |
| 关掉，带确认 | `stop` |
| 按已有模板开一个新 agent | `start` |

**需要内核新能力，做到这一步时先按 DESIGN 第 16 节评估**

- **把别人的接入窗口踢掉**（你说的「unattach」）。现在只有接入的那个窗口自己能按 Ctrl-] 断开，没有命令能从外面断开别的窗口。要做就得在栏位里加一个操作，属于高风险层。先确认是不是真需要：多数情况下，关掉那个窗口就够了。

**不做**

- 在面板里实时显示 agent 的界面、多个 agent 并排显示：需要终端模拟。
- 替 agent 回答权限框或提问框：和 corral 的规矩一致，面板只负责把人带进 attach。

### 怎么算成功

- side project 里一天下来，看状态、接入、送话、关掉这些事都在面板里完成，基本不用再手敲 corral 命令。
- 从面板接入再回来，终端模式都能还原干净，面板显示不乱。

### 止损点

- 发现离不开「在面板里直接看 agent 画面」：停下，这条路需要终端模拟，回到「board 加 attach 分开用」。
- 为了面板不得不给内核加第二个以上的新能力：停下，重新评估边界。

## 不做

- 不做前端，不做多窗格布局，不做终端模拟，不做会话恢复。
- 不做 corral 内部的通知、看板逻辑；配套工具只读公开输出。
- 不在 corral 里加任何「什么时候开谁、送什么」的判断。
